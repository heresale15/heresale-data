1) 추천 배포 방식: GitHub + Netlify 연결 (자동 업데이트에 필요)
-------------------------------------------------------------------
1. github.com에서 새 저장소(예: heresale)를 만들고 이 폴더 전체를 올립니다.
   (숨김 폴더 .github, .well-known 포함)
2. Netlify → Add new site → Import from Git → 그 저장소 선택 → Deploy.
   기존 heresale.netlify.app 사이트를 쓰려면 Site settings → Build & deploy → Link repository.
3. 이후로는 GitHub에 파일을 바꿔 올리면 Netlify가 자동으로 다시 배포합니다.
※ Netlify Drop(끌어다 놓기)도 화면은 동작하지만, 매주 자동 검사(GitHub Actions)는 저장소가 있어야 돌아갑니다.

-------------------------------------------------------------------
2) 자동 업데이트는 이렇게 동작합니다
-------------------------------------------------------------------
[매번 자동]  매장 정보 — 앱을 열 때마다 카카오에서 실시간으로 가져옵니다 (20분 캐시).
[자동 차단]  혜택 데이터마다 '확인 기한(reviewBy)'이 있고, 기한이 지나면 앱이 그 혜택을
             계산에서 자동으로 뺍니다. 확인 안 된 오래된 혜택이 계속 보이는 일을 막습니다.
[매주 자동]  GitHub Actions가 모든 출처 페이지를 열어 내용(숫자·%·원)이 바뀌었는지, 확인 기한이
             2주 안으로 다가왔는지 검사하고, 있으면 GitHub 이슈로 알려 줍니다.
[매월 자동]  Claude 예약 작업이 출처를 다시 조사해 benefits.json 새 버전과 변경 내역을
             '여긴할인' 프로젝트 문서로 만들어 둡니다.
[사람 확인]  새 버전을 확인한 뒤 data/benefits.json을 바꿔 GitHub에 올리면 자동 배포됩니다.
※ 혜택 숫자를 사람 확인 없이 자동으로 고치게 하지 않은 이유: 카드사·통신사 페이지 구조가 자주 바뀌어
  자동 추출이 틀리면 사용자에게 틀린 할인액이 그대로 나가기 때문입니다.

3) 혜택 데이터 고치는 법 (data/benefits.json)
-------------------------------------------------------------------
카드 1장 예시:
  { "id": "shinhan_mrlife", "issuer": "신한카드", "type": "신용카드", "name": "신한카드 Mr.Life",
    "cap": 10000,                       ← 월 한도(원). 0 = 한도 없음, null = 모름
    "rules": [
      { "cats": ["cvs"], "rate": 10 },                                  ← 업종 할인
      { "brands": ["스타벅스"], "rate": 50 },                            ← 브랜드 할인
      { "all": true, "rate": 1.2 },                                     ← 모든 가맹점
      { "brands": ["CU"], "amount": 1000, "min": 10000 },              ← 정액 캐시백(건당 1만원 이상)
      { "cats": ["cafe"], "rate": 10, "when": { "hours": [21, 9] } },   ← 21시~9시만 (days:[0,6]=주말, dates:[1,11]=날짜)
    ],
    "src": "출처 주소", "checked": "확인한 날", "reviewBy": "다시 확인할 날" }
업종 코드: cvs 편의점, cafe 카페, mart 대형마트(이마트·롯데마트·홈플러스·코스트코), super 슈퍼,
          drugstore H&B·생활, bakery 베이커리, dining 외식, culture 영화·서점, fuel 주유
※ 확인한 뒤에는 checked와 reviewBy(보통 60일 뒤) 날짜를 꼭 바꾸세요. meta.checkedAt도 같이.

4) 설정 (app.js 맨 위 CONFIG)
-------------------------------------------------------------------
kakaoRestKey : 카카오 REST API 키. 화면 코드에 보이므로 카카오 콘솔에서 일일 사용량을 확인하세요.
               위치 1번 검색에 최대 160번 호출(보통 40~80번)하고 결과를 20분 저장합니다.
               사용자가 많아지면 Netlify Functions로 키를 숨기고 서버 쪽 캐시를 두는 걸 권합니다.
supabaseKey  : 제보를 받으려면 Supabase publishable(anon) 키 입력.
               benefit_reports 테이블에 anon은 INSERT만 허용하는 RLS 정책을 거세요.
contactEmail : Supabase 대신 이메일로 제보를 받으려면 입력.
※ 이전 버전의 관리자 화면(PIN, 키 입력, 수익 시뮬레이터)은 브라우저에서는 안전하게 만들 수 없어 없앴습니다.

v16에서 추가된 운영 항목
-------------------------------------------------------------------
[로고] logos/ 폴더에 이미지를 넣고 data/logos.json에 "스타벅스": "/logos/starbucks.png" 처럼
       적으면 글자 배지 대신 로고가 나옵니다. 상표권자(각 브랜드) 허락을 받은 로고만 넣으세요.
       파일이 없거나 깨지면 자동으로 글자 배지로 돌아갑니다.
[카드 목록] 혜택을 확인한 카드는 data/benefits.json의 cards에, 이름만 확인한 카드는
       data/cards_catalog.json에 넣습니다. 혜택을 확인하면 catalog에서 cards로 옮기세요
       (같은 이름은 앱이 자동으로 중복 제거).
[지역화폐] data/benefits.json의 localCurrencies. rate가 비어 있으면 사용자가 할인율을 직접 넣어야
       계산됩니다. 지자체 공지로 확인한 뒤 rate·cap·src·reviewBy를 채우세요.
[카드 발급 안내] app.js CONFIG.cardPromo
       - affiliate:false(기본): 카드 정보 페이지(네이버 검색)로만 연결. 수수료 없음, 비교 정보.
       - 발급 수수료를 받으려면 카드사 제휴모집인 계약 또는 금융상품판매대리·중개업 등록이 먼저 필요합니다.
         그 후 affiliate:true, affiliateUrls:{카드id: 링크}, adReviewNo:'여신금융협회 심의필 제…호'를 넣으세요.
         앱에 [광고] 표시와 경고문이 자동으로 나옵니다.
       - 발급 안내에는 월 할인 한도가 확인된 혜택만 나옵니다(한도를 모르면 할인액이 부풀려질 수 있어서).
[결제 기록] 사용자가 [이렇게 결제했어요]로 남긴 기록은 그 기기에만 저장됩니다.
       카드별 남은 한도·전월실적 진행률을 계산하고, 할인 계산에 남은 한도를 반영합니다.
[본인인증 + 카드 내역 자동 불러오기] 본인신용정보관리업(마이데이터) 허가가 필요합니다.
       직접 허가를 받거나, 허가 사업자의 API를 제휴로 쓰는 방법이 있습니다. 그 전까지는 결제 기록으로 대체합니다.

지역화폐·온누리 가맹점 데이터 넣기 (자료가 갱신될 때마다)
-------------------------------------------------------------------
가장 쉬운 방법: 아래 파일을 내려받아 Claude 채팅에 첨부 → Claude가 변환·검증해서 새 web 폴더를 드려요.

직접 할 때:
1. 공공데이터포털에서 CSV 내려받기 (로그인 없이 가능)
   - 동백전:   https://www.data.go.kr/data/15088786/fileData.do  ("부산광역시_지역화폐(동백전) 가맹점 현황")
   - 온누리:   https://www.data.go.kr/data/3060079/fileData.do   ("소상공인시장진흥공단_전국 온누리상품권 가맹점 현황")
   - 인천e음:  https://www.data.go.kr/data/15146286/fileData.do  ("인천광역시_인천데이터포털_지역화폐가맹점 정보")
2. 명령 프롬프트에서
     cd C:\heresale\web
     node tools/build-merchants.js dongbaek "C:\Users\내이름\Downloads\동백전파일.csv"
     node tools/build-onnuri.js "C:\Users\내이름\Downloads\온누리파일_20260731.csv"   (온누리는 주소가 없어 전용 변환기 · 파일 이름의 날짜를 기준일로 씀)
     node tools/build-merchants.js incheon_eum "C:\Users\내이름\Downloads\인천파일.csv"
   → data\dongbaek, data\merchants\onnuri, data\merchants\incheon_eum 폴더에 시·군·구별 파일이 만들어져요
   (--basis는 파일에 기준일 열이 없을 때 파일 이름의 날짜를 적어 주세요)
3. web 폴더를 Cloudflare에 다시 올리고 새 버전을 100%로 배포하면 끝. 앱은 다시 빌드하지 않아도 돼요.
- 앱은 자료가 있는 상품권만 매장 옆에 "동백전", "온누리"처럼 표시하고, [가맹점만] 버튼을 보여 줘요.
- 자료에 없는 새 가맹점이 있을 수 있어, 앱은 "목록에 없어요 (기준일)"로만 표시해요.
- 서울사랑상품권 가맹점 자료(서울 열린데이터광장)는 "상업적 이용금지" 조건이라 넣지 않았어요.
